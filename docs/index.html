Project documentation

Build useful PHP pages, without a framework

rpfiles is a PHP helper library for MySQL database actions, request values, common application helpers, and Zoho Books API calls. Use it in regular PHP pages; no MVC framework is required.

PHP 8.0+ MySQL / mysqli Composer cURL for Zoho/API

Overview

ConnectOpen a MySQL connection with environment configuration.
CRUDInsert, select, update, and delete with prepared values.
Request helpersRead GET and POST values with convenient type helpers.
Zoho BooksUse the included API client for Books integrations.
What it does not do:

rpfiles is a helper library, not a framework. It does not create your database, tables, routes, login flow, or application authorization rules.

Installation

If the package is not available on Packagist, register its GitHub repository and install the development branch:

composer config repositories.rpfiles vcs https://github.com/rahulphp6/rpfiles
composer require rahulphp6/rpfiles:dev-main

Load Composer's autoloader in your PHP entry point:

<?php
require __DIR__ . '/vendor/autoload.php';

use Rahul\Helpers\RpAction;

Database configuration

RpAction::OpenCon() reads the following keys from $_ENV. Configure them in your bootstrap or environment loader; the library does not load .env files itself.

KeyPurposeDefault
DB_HOSTMySQL hostlocalhost
DB_USERMySQL usernameroot
DB_PASSMySQL passwordEmpty
DB_NAMEDefault databaselogistic_db
 
<?php
// Set these securely via your app's environment/bootstrap configuration.
$connection = RpAction::OpenCon();

// Optionally select a specific database:
$otherConnection = RpAction::OpenCon('reporting_database');

Most secureDbAction() calls open their own connection, so calling OpenCon() first is optional.

Database CRUD, one page at a time

The examples use a customers table. Create your schema before using the helpers:

CREATE TABLE customers (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(150) NOT NULL,
    email VARCHAR(254) NOT NULL
);

secureDbAction() action codes

CodeActionTypical result
1Insertsuccess and new insert_id
2Updatesuccess and affected_rows
3Deletesuccess and affected_rows
4Selectsuccess and rows in data
5List columnssuccess and column names in data

Signature: secureDbAction($table, $action, $data = [], $where = '', $params = [], $db = null). The $where fragment does not include the word WHERE. Use ? placeholders for values and pass those values in $params.

Add a record

<?php
$name = RpAction::safePost('name', '', false);
$email = RpAction::safePost('email', '', false);

if ($name === '' || !filter_var($email, FILTER_VALIDATE_EMAIL)) {
    // Show a validation message.
} else {
    $result = RpAction::secureDbAction('customers', 1, [
        'name' => $name,
        'email' => $email,
    ]);

    if ($result['success']) {
        $newCustomerId = $result['insert_id'];
    } else {
        // Log the error safely; do not expose database details to visitors.
    }
}

Read records

$result = RpAction::secureDbAction(
    'customers',
    4,
    ['columns' => 'id, name, email', 'orderBy' => 'id DESC', 'limit' => 20],
    'email = ?',
    ['person@example.com']
);

if ($result['success']) {
    foreach ($result['data'] as $customer) {
        echo htmlspecialchars($customer['name'], ENT_QUOTES, 'UTF-8');
    }
}

Select options include columns, orderBy, limit, and offset. Escape database content when displaying it in HTML.

Edit a record

$customerId = RpAction::safePostInt('id');
$name = RpAction::safePost('name', '', false);

if ($customerId > 0 && $name !== '') {
    $result = RpAction::secureDbAction(
        'customers',
        2,
        ['name' => $name],
        'id = ?',
        [$customerId]
    );
}

Delete a record

$customerId = RpAction::safePostInt('id');

if ($customerId > 0) {
    $result = RpAction::secureDbAction(
        'customers',
        3,
        [],
        'id = ?',
        [$customerId]
    );
}
For write actions:

Use a POST form for deletes, ask for confirmation, and check that the signed-in user is authorized to change that record. The helper does not implement these application rules.

GET and POST helpers

$search = RpAction::safeGet('search', '');
$page = RpAction::safeGetInt('page', 1);
$active = RpAction::safePostBool('active');

// false skips HTML escaping; validate input, bind it in SQL,
// and escape it later for the output context.
$rawName = RpAction::safePost('name', '', false);
HelperBehavior
safePost($key, $default, $sanitize)Reads POST; strings are trimmed and HTML-escaped by default.
safeGet($key, $default, $sanitize)Reads GET; strings are trimmed and HTML-escaped by default.
safePostInt(...), safeGetInt(...)Cast the provided value to an integer.
safePostBool(...), safeGetBool(...)True only for the string '1' or 'true'.

These are convenience helpers, not complete input validation. Validate according to your application's requirements and escape output for its context.

Other RpAction helpers

Helper(s)What they are for
getRowById($table, $id)Return one row using a prepared ID value.
redirectTo($path)Redirect to a path and exit.
isAdmin(), isUser(), checkUser(), isShop(), isSuper()Role checks based on the session's role; isUser('location') returns a location ID when found.
isPermMode(...), isModCheck(...)Permission lookups that expect the application's permissions tables.
renderDropdown(...), renderColName(...)Build/output a database-backed select; quick-add needs matching application UI.
mgs(...), alert(...)Output alert markup/scripts; only use trusted or correctly escaped messages.
flattenStdClass(...), array_map_deep(...), is_multi(...), progress(...)General data and display utilities.
lastId(...), colSum(...), getTotal(...), table_sum(...)Legacy database lookup and aggregate helpers.
Legacy SQL helpers need extra care.

dbAction(), queryRun(), getRow(), getName(), and aggregate helpers may accept or construct SQL fragments. Only pass trusted, application-controlled table names, columns, and conditions; prefer prepared statements for request values.

Role and permission helpers rely on the consuming app's session/database conventions. Start and protect the session yourself, then enforce permissions on every server-side action.

Security: what is and is not protected

Prepared values help prevent SQL injection.

secureDbAction() binds database values using prepared statements. Keep table names, columns, selected fields, ordering, and SQL fragments fixed or allow-listed because those query parts are not bound values.

  • safePost() and safeGet() do not authenticate users or authorize actions.
  • They do not provide CSRF protection or enforce business validation.
  • HTML escaping for request strings does not replace output escaping for other contexts.
  • Do not expose database errors, raw SQL, credentials, or sensitive query data to visitors.
  • Protect database and OAuth credentials; do not commit secrets.
  • Legacy raw-SQL helpers are not a replacement for prepared statements.

Zoho Books

The library also provides a Zoho Books client. A basic API call looks like this:

<?php
use Rahul\Helpers\ZohoBooks;

$client = new ZohoBooks($accessToken);
$response = $client->request('contacts', 'GET');

OAuth/token helpers need valid Zoho settings and application-specific configuration. The existing token integration expects constants such as client_idb, client_secretb, BASE, organizationId, and common_db, along with a token table. Keep credentials private.

Development and local demo

Run the package smoke test from the project root:

composer install
composer test

The smoke test checks Composer autoloading; it does not connect to MySQL or call Zoho.

To run the example page locally, configure your MySQL connection in PowerShell, then start the PHP server from the project root:

$env:DB_HOST = "127.0.0.1"
$env:DB_USER = "root"
$env:DB_PASS = "your-local-password"
$env:DB_NAME = "your-database-name"
php -S 127.0.0.1:8000 -t examples

Use a database containing a customers table, then visit http://127.0.0.1:8000/. The example displays at most 20 customer rows and does not call Zoho. Stop the server with Ctrl+C.
